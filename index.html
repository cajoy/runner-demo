Run the preflight workflow locally, then inspect its task receipts and compare the next run. This static preview shows the demo UI and the numbers this page states; it does not certify that this commit has a signed receipt or that CI skipped its tasks. The receipt does that.

Receipt and signature

A bounded record of one finished run, signed on the machine that produced it.

Signature
Ed25519 over the receipt bytes, carrying the signer id that made it.
Trust
Policy on protected main pins each signer's public key, scoped to repository, tasks, placement and platform.
Binding
Commit, tree and config digest, so proof cannot drift onto other code.
Integrity
A digest of immutable receipt bytes, with the time they were created.

Anatomy

Seven groups, so ambiguity has somewhere to be recorded.

  • Producer
  • Run identity
  • Subject
  • Outcome
  • Mutation
  • Authority
  • Integrity

What it does not claim

  • A terminal outcome for one exact run. Not current runtime health, and not permission to run again.
  • Complete structure is not verification. Signatures, source bytes, policy and runtime are checked by the verifier.
  • A complete envelope can still report an unknown outcome, and a consumer has to preserve that uncertainty rather than resolve it.
